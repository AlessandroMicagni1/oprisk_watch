# OpRisk Watch

EU & Swedish operational-risk regulatory monitor. Aggregates agency news (RSS)
and the full EUR-Lex legislation database (SPARQL), stores everything in SQLite,
and serves a fast, searchable Streamlit UI.

## Architecture (Phase 0–1)

| Module | Responsibility |
|--------|----------------|
| `config.py` | Endpoints, keyword/term defaults, DB path |
| `sources.py` | The RSS source registry |
| `util.py` | Text cleaning, summaries, date parsing, hashing |
| `fetch.py` | I/O: RSS + EUR-Lex SPARQL → normalized items |
| `store.py` | SQLite: schema, idempotent upsert, queries, health |
| `fetch_job.py` | Standalone fetcher (cron / manual) → writes to DB |
| `ui.py` | Streamlit UI — **reads only from SQLite** |
| `app.py` | Thin entry point (`streamlit run app.py`) |

The UI never fetches on load — it reads the database. Fetching happens only when
you click **Fetch now** or run `fetch_job.py`. That's what makes it instant and
lets history accumulate past the RSS window.

## Run

```bash
pip install -r requirements.txt
python fetch_job.py       # first fetch → populates oprisk.db
streamlit run app.py      # view (loads instantly from the DB)
```

You can also just `streamlit run app.py` and click **Fetch now** in the sidebar.

## Notes

- `oprisk.db` is git-ignored and regenerated by fetching.
- On Streamlit Community Cloud the disk is ephemeral; durable multi-user storage
  is Phase 6 (scheduled job + external store).
